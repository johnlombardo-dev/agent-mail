## Rejected shortcuts

- HTTP status to exit tables: one 409 or 500 status has several typed meanings.
- Error.message inspection: messages are mutable presentation and may contain hostile or secret material.
- Boolean success plus optional warning: it cannot represent partial, uncertain, stale, or attention values constructively.
- A raw special case in each command: it duplicates TTY, backpressure, cancellation, and partial-write policy.
- Immediate process exit in a signal handler: it skips awaited cleanup and makes terminal races nondeterministic.
- Treating completed action state as sufficient: the shared response can still omit or duplicate frozen-target results.
- A local routing preview exception map: it would widen feature semantics outside the accepted operation contracts.

## Change rule

Within v1, an existing kind, number, code/details mapping, destination, framing rule, mode compatibility rule, or classifier meaning cannot change. An additive operation may reuse an existing kind only after the oracle gains exact applicability and constructive proof. A new semantic kind or changed number requires a new oracle version and migration note.

## #220 reconciliation

Issue #220 supplies exactly three additive `routing.commit` error mappings at HTTP 409: `routing.preview_replayed` to replay/82, `routing.preview_expired` to expired/81, and `routing.preview_tampered` to tampered/83. This preserves every #213 semantic, exit, destination, framing, and classifier choice; no global error applicability or CLI-private mapping is added.
