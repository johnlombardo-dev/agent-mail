## Consequential review points

Independent review must explicitly accept or reject D02, D16, D17, D21, D23, and D24. They resolve intersections in accepted artifacts without changing those artifacts:

1. `failed` must exist internally but is absent from the public enum.
2. The response schema permits intermediate accepted shapes, while downstream pause/stop postconditions require stable completion before success.
3. `authBlocked` plus explicit pause is not spelled out by an upstream transition table.
4. The public version is monotonic only within one actor incarnation because no accepted artifact owns durable cross-process version allocation.
5. Credential repair is admitted only after stable `authBlocked`; no revision latch replays a change that arrived during cleanup.
6. Supervisor request IDs correlate edge-triggered intents but do not deduplicate a request delivered after an earlier cleanup has completed.

A rejected point needs an exact alternative that preserves P1-C08 schemas, F19 observation closure, zero live work in paused/stopped/authBlocked, and the no-automatic-auth-retry rule. Implementation must not choose another behavior locally.

## Residual boundaries

No statechart behavior is optional or unresolved. Three integration inputs remain outside this contract's authority and are explicit in the model:

- The daemon bootstrap owner decides whether process launch sends start (`R01`).
- P3-C17/P3-C21 supply numeric retry and timer configuration within frozen bounds (`R02`).
- A public `expectedVersion` field requires a separate contracts revision (`R03`).

None permits an implementation to add a mode, event, actor, timer, cleanup path, response state, or hidden default to this candidate.
