## Executable design probes

Run:

```sh
node docs/architecture/action-approval-authority-check.v1.mjs
```

The checker hashes the oracle, checks all frozen source inputs, validates every cross-reference and required case, confirms the authority/profile/schema/error/retirement structure, and runs these executable in-memory authority transitions:

| Probe                  | Input / attack                                                                                                        | Exact pass condition                                                                                         |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `P-SAME-TOKEN`         | Combined approve+commit scope, operator trying commit, agent trying approve, or committer principal equal to approver | Profile construction or consume rejects; no claim, executor capability, or remote call                       |
| `P-SPOOFED-PRINCIPAL`  | Add principal, credential, profile, scope, presence, time, or nonce fields to strict request JSON                     | Boundary rejects 400 or field has no schema location; auth context remains authoritative                     |
| `P-CHANGED-BINDING`    | Independently change request digest, stored targets, action/intent, plan version, or seal                             | Mismatch/stale error, full rollback, zero remote calls                                                       |
| `P-EXPIRED`            | Consume at exact approval expiry, after approval expiry, or after plan expiry                                         | Stable 409, durable expiry where applicable, no claim or remote call                                         |
| `P-CONCURRENT`         | Race two agent committers against one approval                                                                        | One receipt, one claim, one version transition, one possible executor start; loser gets consumed 409         |
| `P-RESTART-BEFORE`     | Restart after approval persistence but before consume                                                                 | Approval reopens available only when current and verifiable                                                  |
| `P-RESTART-AFTER`      | Crash after consume transaction but before dispatch                                                                   | Receipt/claim/executing reopen together; replay cannot consume again; recovery resumes once                  |
| `P-AUDIT-REOPEN`       | Reopen after creator, A1 approval, consume, attempt, and terminal audit                                               | Byte-stable actor/result and authority-instance/challenge/assertion provenance; receipt remains closed       |
| `P-PARITY`             | Exercise distinct strict direct, composed HTTP, CLI-to-HTTP, repository, and recovery boundary functions with traces  | Direct/HTTP/CLI delegate exactly once to the service; only it uses the repository; recovery never consumes   |
| `P-CANCEL-RACE`        | Bind cancellation to exact DELETE/path/raw body, then race fresh signed cancellation with agent consume               | Binding mutations reject; exactly one closure wins; cancellation causes no effect and cannot undo consume    |
| `P-PARTIAL-UNCERTAIN`  | Fail or crash after one or more target dispatches                                                                     | Receipt stays consumed; attempts/results keep executor attribution; only read-only reconciliation proceeds   |
| `P-LEGACY`             | Open pre-migration pending, executing, and terminal rows                                                              | Pending cannot approve/commit; executing begins no undispatched effect; terminal is visibly legacy-untrusted |
| `P-PRESENCE-BINDING`   | Sign an A1 P-256 challenge, then mutate method, concrete path, raw body/digest, signature, instance, or ceremony use  | Only the exact current low-S P1363 assertion passes; all mutations and approve/cancel cross-replay reject    |
| `P-RESTORE-ROLLBACK`   | Restore pre-consume and pre-cancel backups on the original host with every old credential and seal key still present  | Admission invalidates all restored available challenges and unconsumed approvals before listeners/recovery   |
| `P-OPERATOR-SESSION`   | Mint a session, exercise create/inspect, then attempt approve/commit, restart, config drift, and expiry               | Only create/inspect work while current; the memory-only bearer never becomes approval or commit authority    |
| `P-RESTORE-CONSUMED`   | Back up after consume/before dispatch, dispatch on the original timeline, then restore with the old host keys         | Exact event/time, receipt/plan/claim, disposition/sentinel, and digest persist; cross attribution rejects    |
| `P-CLOSURE-REAPPROVAL` | Expire or invalidate an available approval and regenerate the preview                                                 | Plan advances exactly once; a new-version approval succeeds and the closed artifact remains unusable         |
| `P-SEAL-KEYRING`       | Tamper/miss/rotate/remove keys, attempt active/missing removal, and inspect a database backup                         | Active/missing removal rejects without mutation; verify-only removal and key faults fail closed              |
| `P-CONFIG-RACES`       | Order revoke-vs-consume and rotated verify-only-key-removal-vs-consume                                                | The first linearized action wins; later mutation cannot erase a returned receipt/capability                  |
| `P-CHALLENGE-CAPACITY` | Exercise two credentials, expiry reclamation, per-credential rate/slots, and 128 global slots                         | Counters are per credential, expired rows do not occupy slots, and exact local/global bounds reject          |

These are design proofs, not implementation acceptance evidence. #204 must reproduce the vectors against real strict schemas, SQLite transactions, handlers, composed HTTP, CLI-driven requests, executor call traces, restart processes, and backup/reopen behavior.

## Required implementation parity matrix

| Recovery        | Receipt-linked executing candidate only after ordinary restart; read-only reconciliation            | Reconsume, missing receipt, `restore-quarantined`, restored live authority, undispatched legacy effect | Child-process crash boundaries plus pre-consume/pre-cancel/post-consume backup restores     |
