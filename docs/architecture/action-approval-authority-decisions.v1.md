# Action approval authority decisions v1

Normative oracle: `action-approval-authority-oracle.v1.json`

Oracle SHA-256: `4042c52dfe8c9377f722cbde465b9d7a3eb0af3b995863d649c8f37754474768`

This is a checked decision and retirement view. The oracle is normative.

## Accepted decisions

| ID    | Decision                                                                                                                                               | Consequence                                                                                                                                                             |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `D01` | Adopt user-selected Policy A.                                                                                                                          | A human-present operator approves; a distinct unattended agent later consumes and commits.                                                                              |
| `D02` | Separate credential profiles structurally and compare principal and credential IDs at consume.                                                         | Neither a combined scope set nor two credentials for the same principal satisfy independence.                                                                           |
| `D03` | Use user-selected A1: a macOS Secure Enclave P-256 key protected by device-owner presence, a daemon challenge, native broker, and daemon verification. | A prompt, TTY, static bearer, software key, or caller claim is not human-presence authority.                                                                            |
| `D04` | Rename the domain act and public surface from authorize to approve.                                                                                    | “Authorization” remains generic access control and cannot masquerade as durable approval.                                                                               |
| `D05` | Allow either accepted public profile to create, with an A1 non-approval session required for operator create/inspect.                                  | An operator or agent can prepare a plan, but creation never grants approval.                                                                                            |
| `D06` | Canonicalize exact arrays, hash them with SHA-256, and seal approval using HMAC-SHA-256 under a separate daemon key.                                   | Stored-field tampering is detectable before consume.                                                                                                                    |
| `D07` | Cap approval at 600 seconds and the earlier plan/credential expiry.                                                                                    | `now >= expiresAt` always fails closed.                                                                                                                                 |
| `D08` | Persist an immutable approval plus constructive closure rows.                                                                                          | Consumed, expired, cancelled, and invalidated authority never reopens.                                                                                                  |
| `D09` | Consume, receipt, claim, receipt/claim link, and plan transition in one `BEGIN IMMEDIATE` transaction.                                                 | Replay, concurrency, and crash cannot split authority from execution claim.                                                                                             |
| `D10` | Return stable 409 `action.approval_consumed` on every replay.                                                                                          | Inspect, not a repeated commit, recovers state after response loss.                                                                                                     |
| `D11` | Let only the same operator principal cancel with fresh presence; race cancellation atomically with consume.                                            | Exactly one closure wins and cancellation cannot undo a committed consume.                                                                                              |
| `D12` | Increment a still-pending plan version after expiry, cancellation, or invalidation.                                                                    | Replacement approval requires a newly verified preview.                                                                                                                 |
| `D13` | Keep executor authority internal and persist receipt-linked attempt attribution before adapter permission.                                             | No bearer or public route can become an executor shortcut.                                                                                                              |
| `D14` | Keep approval consumed across partial and uncertain outcomes.                                                                                          | Failure or ambiguity never replenishes mutation authority.                                                                                                              |
| `D15` | Distinguish ordinary restart from explicit database restore.                                                                                           | Restart may retain current authority; restore invalidates unconsumed authority and quarantines consumed/executing snapshots before recovery, even when old keys remain. |
| `D16` | Mark all legacy plans untrusted and never infer missing authority.                                                                                     | Scope-only pending plans cannot approve/commit; executing legacy plans start no new undispatched effect.                                                                |
| `D17` | Publish safe principal/profile attribution and keep credential/seal material internal.                                                                 | Audit is useful without turning secrets into responses or logs.                                                                                                         |
| `D18` | Use one strict contract and consume service across direct handler, HTTP, CLI, storage, and recovery composition.                                       | Adapters cannot invent alternate authority.                                                                                                                             |
| `D19` | Bind approve POST and cancellation DELETE independently to exact concrete paths and SHA-256 of the final raw bounded body bytes.                       | Ceremony uniqueness spans both operations; method, path, body, or cross-operation replay fails.                                                                         |
| `D20` | Preserve authenticate-before-read with two-phase operator authentication.                                                                              | Bounded assertion/challenge preflight precedes streaming; strict parse, raw digest comparison, signature verification, and atomic challenge consumption follow.         |
| `D21` | Seal every approval immutable field except the seal output exactly once using a machine-checked ordered projection.                                    | User-presence time, request binding, authority/config revisions, seal key ID, and algorithm cannot drift outside the commitment.                                        |
| `D22` | Mint a memory-only, at-most-600-second A1 operator session with exactly create and inspect scopes.                                                     | The low-friction session cannot approve, cancel, commit, or survive restart/configuration change.                                                                       |
| `D23` | Give every A1 operator credential an exact 365-day lifetime; equality is expired and expiry cannot be extended.                                        | Rotation and recovery create a new credential and lifetime rather than inventing indefinite authority.                                                                  |
| `D24` | Use the exact owner-only 32-byte approval seal keyring lifecycle, excluded from every backup and diagnostic surface.                                   | Rotation retains verify-only keys; only verify-only keys may be removed, active/missing removal rejects, and missing keys never regenerate.                             |
| `D25` | Linearize authority admission and outside-DB credential/key changes under one ordered file/process/SQLite lock protocol with revision rechecks.        | Revocation or removal cannot linearize first while a later consume still returns an executor capability.                                                                |
| `D26` | On explicit restore, make every restored receipt-backed executing plan terminal `restore-quarantined` before recovery.                                 | Audit remains available, but the restored timeline has no path to a new remote effect.                                                                                  |
| `D27` | Freeze strict reason pairs, constructive closure versions, receipt/claim linkage, and terminal receipt/plan/claim attribution.                         | #204 can implement DDL, triggers, and audit attribution without selecting storage semantics.                                                                            |
| `D28` | Require a daemon-issued one-use A1 challenge for every seal-key rotation or removal, bound to exact target and expected revision.                      | Same UID and a client prompt are insufficient; only the current Secure Enclave operator key can authorize one mutation.                                                 |

## Rejected alternatives

| ID    | Alternative                                                               | Rejection                                                                                                                        |
| ----- | ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `R01` | Policy B, where operator confirmation commits immediately                 | The user selected later unattended consume under Policy A.                                                                       |
| `R02` | One bearer with separate approve and commit scopes                        | A single bearer can perform both ceremonies and self-authorize.                                                                  |
| `R03` | Same principal with two credential strings                                | It fails the selected distinct unattended agent principal rule.                                                                  |
| `R04` | TTY prompt or `--yes` as presence proof                                   | The daemon cannot independently verify a client-side prompt.                                                                     |
| `R05` | Caller-supplied identity, presence, time, scope, target, or intent fields | The acting caller could manufacture its own authority.                                                                           |
| `R06` | Plain unsealed approval database row                                      | Database tampering would not be independently detectable.                                                                        |
| `R07` | Consume first, persist receipt or claim later                             | Crash and concurrency windows could reuse authority or execute without attribution.                                              |
| `R08` | Return commit success idempotently on replay                              | It obscures the one-use boundary; inspect provides safe recovery.                                                                |
| `R09` | Reuse approval after partial, failed, cancelled, or uncertain execution   | A remote effect may already exist and approval is outcome-independent one-use authority.                                         |
| `R10` | Backfill legacy scope-only rows as trusted                                | Missing creator, approver, presence, binding, seal, and receipt facts cannot be inferred.                                        |
| `R11` | Back up HMAC secrets alongside the database                               | A copied data backup would retain live mutation authority and couple data/secret recovery.                                       |
| `R12` | Public executor token, scope, route, or CLI command                       | It bypasses approval consumption and executor isolation.                                                                         |
| `R13` | WebAuthn/FIDO2 A2 authenticator                                           | The user selected macOS-native A1; A2 introduces materially different origin, provisioning, portability, and UX policy.          |
| `R14` | Software P-256 key, passphrase, static bearer, or prompt-only fallback    | Fallback could let unattended same-user software obtain or replay approval without independently verified device-owner presence. |
| `R15` | Bind a canonical JSON reserialization instead of transmitted body bytes   | It detaches the assertion from byte-level ingress; A1 binds the exact bounded bytes that the daemon parses.                      |
| `R16` | Require a fresh Secure Enclave ceremony for every operator create/inspect | It adds avoidable friction; the bounded non-approval session preserves separation.                                               |
| `R17` | Give the operator session approval/commit scope or accept it as presence  | A reusable bearer would become ceremony or mutation authority and recreate self-authorization.                                   |
| `R18` | Treat explicit restore like ordinary restart for consumed work            | A restored pre-dispatch snapshot can replay an effect already dispatched on the original timeline.                               |
| `R19` | Update credential/key files and approval rows under independent locks     | Consume could validate stale authority after revocation/removal and still return a capability.                                   |
| `R20` | Omit credential expiry or regenerate a missing keyring                    | Either invents authority not derivable from trusted durable state.                                                               |
| `R21` | Accept a same-UID bare seal-key discriminant after a client-side prompt   | The daemon cannot verify that ceremony, so unattended same-UID software could cause rotation/removal denial of service.          |

## Decision closure

`remainingConsequentialChoices` is empty in the oracle. A1 also freezes Keychain accessibility, presence evaluation, signature encoding, challenge lifecycle, raw request binding, enrollment/configuration, revocation/rotation, unsupported-hardware behavior, and restore invalidation. Implementation may choose internal module and symbol names only when they do not change the frozen public names, profiles, fields, algorithms, time limits, errors, storage facts, transitions, migration behavior, or proofs. Any such change requires a new oracle digest and review before #204 proceeds.
